# Product

<!-- impeccable:product-schema 1 -->

## Platform

macos-native (AppKit code-only UI; not among the web/ios/android enum values, recorded as is. The design language takes macOS desktop conventions as its baseline)

## Stack

Swift 6 + AppKit pure programmatic UI, SwiftPM build without Xcode (CLT), composable execution meta-architecture (pods + META_COMPLIANCE + pod-lint gate). UI rendering may only use AppKit view-layer capabilities (layer-backed NSView / Core Animation / NSVisualEffectView / SF Symbols / NSWorkspace file icons); there is no web stack.

## Users

Primary user: the project owner, a heavy file-management user on macOS 27 and a paying QSpace Pro customer (building a replacement because of QSpace's stutter and high CPU), with a developer-style workflow combining a terminal (iTerm) and multiple panes. Target audience once open source: similar power users who find Finder's information density too low and want multiple panes, a stash shelf and direct keyboard access.

## Product Purpose

A native macOS file manager replacing Finder and QSpace: multi-pane (one/two/three/four) layouts, window-level workspace tabs, stash shelf, focused search (including a hidden-file channel, going beyond QSpace), archives, a bookmark sidebar and Space preview. Success criteria: interaction density and features on par with QSpace, performance significantly better (north star: 0.0% idle CPU with four panes).

## Positioning

"QSpace's features, Finder's native feel, performance nobody else has": direct-child FSEvents filtering plus background pane suspension give zero idle cost, which QSpace cannot do on macOS 27. Open-source differentiation (the user's own words, 2026-08-26, translated): fully custom-drawn UI/UX, maximum customization, "something distinctive when open-sourced". The visual identity itself is one of the selling points.

## Operating Context

A desktop tool left running for long periods, coexisting with iTerm, Bandizip and others; dark and light must both be good (following the system); double-clicking archives and the like always goes to the system default app; launched by third-party apps as the public.folder default handler. Multiple panes on screen plus sidebar and stash shelf is the normal view.

## Capabilities and Constraints

- The structural topology is settled (not a variable of the visual direction): left column = stash shelf (top) + sidebar with bookmark/iCloud/volume groups, running full height; right column = custom-drawn top deck (workspace tab bar + toolbar + address bar) + pane matrix + bottom status bar. M17 decision: drop the system NSToolbar and custom-draw the entire top bar.
- Hard constraints for Operate mode: information density ≥ QSpace (the user repeatedly called out space usage); expression must not obscure tasks, status or familiar affordances.
- Meta-architecture gates: BG-1 (presentation layer may not use write file APIs), FG-1..FG-6 (no fake buttons/craftsmanship invariants), externalized configuration (theme color/font size/appearance are already in Preferences, new tokens always go through externalization), implicit semantics > explicit text (icons first).
- The performance north star must not regress: 0.0% idle CPU with four panes; custom drawing must not introduce constant redraws.
- All shortcuts go through the KeyBindings registry, never hardcoded.

## Brand Commitments

Name: HSpace. The icon exists (generated by scripts/make-icns.sh). Visual commitments explicitly bound by the user (own words, 2026-08-26, translated, permanently in force):
- **Colors use the current theme system** (Theme.accent / Preferences.appearanceMode / accentColorHex), rejecting "flashy web color schemes". The colorful-world direction has been vetoed by the user. The visual standard = a native macOS professional tool (Finder's material language × QSpace's density), with character coming from structure, layout and craftsmanship, not color.
- A **hybrid** of custom drawing and native ("native and custom mixed like QSpace, for example global search can use the native component already implemented"): identity customization concentrates on everyday main views such as the top deck, panes, stash shelf and sidebar; components that already work well natively, such as the search panel, settings window, system dialogs and Quick Look, stay native.
- Open-source recognizability ("distinctive"); QSpace is a benchmark for features and density, not an object of visual imitation (flagged as inference: the earlier "make it exactly like QSpace" referred to stash shelf interaction density, and the fully custom-drawn decision of 2026-08-26 replaced the route of visually copying QSpace).

## Evidence on Hand

A running v0.8.0 app (build/HSpace.app); the UISelfTest self-rendered screenshot pipeline + scripts/ui-smoke.sh regression; several QSpace/Finder screenshots provided by the user (density and layout benchmarks). No marketing assets and no user testimonials; the open-source README screenshot is the storefront.

## Product Principles

1. Density is respect: showing more columns, more rows and less padding on the same screen respects a power user's time.
2. Zero idle cost: every visual proposal must pass the north star first; decoration may not burn CPU constantly.
3. Implicit semantics, direct access: icons plus small tooltips carry operations; text appears only where an icon cannot.
4. State is always visible: which pane has focus, how far an operation has got, what's on the stash shelf. A glance must tell you.
5. Externalize everything: visual tokens (color/font size/density) go into Preferences, users can change them, and open-source users can fork their own skin.

## Accessibility & Inclusion

Fully keyboard-reachable (shortcut registry); light and dark both supported; visible focus states. No confirmed additional standards requirements (undecided, recorded as is).
